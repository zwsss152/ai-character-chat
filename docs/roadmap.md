# 学习与研究路线

时间由理解程度决定。每次选择一个小问题，先提交本人尝试，再寻求提示。

| 后续任务 | 前置知识 | 研究问题与最小实验 | 验收证据 |
|---|---|---|---|
| 读懂骨架 | Python函数、对象、JSON、HTTP | 手工追踪一次请求；改一张角色卡 | 能解释模块输入输出并定位错误 |
| 接真实模型 | 网络请求、异常、消息格式 | 对比固定输入、参数与失败 | 调用记录、用量、错误处理与独立解释 |
| 角色提示 | 消息、上下文、评价规则 | 相同问题比较两种角色卡 | 固定问题、评分、失败分类 |
| 对话上下文 | 列表、Token预算、序列化 | 截断与摘要有什么损失？ | 对照结果与遗漏分析 |
| 长期记忆 | 数据库、用户与角色隔离 | 什么该存，何时更新，如何删除？ | 更新/删除/隔离测试与记忆质量分析 |
| 世界观RAG | 文件、向量、相似度 | 直接提供资料、关键词和向量检索对照 | 检索片段、来源、答案与失败归因 |
| 工具/Agent | 函数、结构化输入、状态 | 固定流程与模型选择工具对照 | 选择错误、参数验证、效果与成本 |
| 评测 | 基线、指标、抽样与重复 | 怎样判断人设一致性与方法有效？ | 完整测试结果、评分规则和限制 |
| 网页客户端 | HTML/CSS/JS、HTTP | 用同一后端展示角色选择与回复 | 自己实现调用、解释网络错误 |
| 训练研究 | 数学、ML、PyTorch、论文 | 小规模微调是否改善有限问题？ | 数据划分、训练日志、基线与复现 |

## 一次研究怎样做

提出具体问题 → 写可反驳的假设 → 建立简单基线 → 固定测试与评价 → 改一个因素 → 分析全部结果与失败 → 决定下一次实验。

同时改变多个部分时，只能比较整体方案，不能把改善归因于其中一个部分。保留新问题用于后续验证，避免只在熟悉题目上调参。
