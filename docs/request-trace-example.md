# 一次完整请求追踪

下面使用**特意编写的虚构输入和离线 mock**，由当前接口实际生成，不包含真实用户记录或密钥，不证明角色能力。临时数据库在生成后移除。会话 ID、时间和耗时每次运行都会变化；时间采用 UTC。

## 复现步骤

1. 默认 mock 模式启动服务，在网页新建露米会话。
2. 发送「我在找空中图书馆的目录。」。
3. 发送「你会怎样核对一条没有来源的记录？」。
4. 在开发追踪中检查第二次请求；也可按 README 的 PowerShell 示例 GET 对应 trace。

第二轮模型输入包括角色设定、配置开场白、第一轮完整问答、当前输入。数据库随后有开场白和两个完整问答；trace 只包含调用时已有的消息，不包含这次回复。

## 怎样读这份记录

- 第一条 `system` 来自创建会话时的角色快照，包括身份、价值观、表达、边界和示例。示例在设定里，不算会话历史。
- 第二条 `assistant` 是配置开场白，没有模型调用。
- 随后的 `user`、`assistant` 是此前已成功提交的完整轮次，最后 `user` 是当前问题。
- `available_turns` 是已有完整轮数，`included_turns` 是实际使用轮数；历史裁剪时两者不同，数据库原文仍保留。
- `characters` 是各条消息正文的字符数总和，不是 token 估计。超预算时最旧完整轮次先被排除。
- `mode=mock`、`model=mock-echo` 表示离线回显；`usage=null` 表示没有模型 token 用量，不能解读为真实服务免费。
- `elapsed_ms` 是当前本地生成流程耗时。失败追踪使用 `status=error` 和安全的 `error_code`，失败不保存半轮对话。

真实服务也使用同一输入格式，但回复质量、计费和人设一致性必须独立验证。追踪会保存聊天内容，只用于本机开发；实际用户记录与本地数据库不应提交仓库。
