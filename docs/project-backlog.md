# 每日开发任务

目标：几个月内逐步形成可用的原创角色对话系统。每天选择一个主要任务，可以拆为功能、验证和必要文档等几项改动；按验收结果提交，不人为拆分无意义提交。

任务按顺序推进，下面的“第几天”是开发日，不是无人值守的自动计划。每次开发后更新实际状态；复杂任务可以延长，未通过验收不算完成。真实模型、服务费用和部署所需条件就绪后再推进对应任务。

## 后续几个月

| 阶段 | 迭代方向 | 阶段验收 |
|---|---|---|
| 第1个月 | 稳定网页、会话、真实模型与最小评测 | 能运行完整对话，有可复现的效果基线 |
| 第2个月 | 世界观RAG、检索评测、历史摘要 | 用对照实验判断检索和摘要是否改善目标问题 |
| 第3个月 | 用户可查看、修改、删除的长期记忆；基础工具调用 | 记忆隔离与更新可验证，工具参数和失败可控 |
| 第4个月起 | 稳定性、延迟与成本优化；部署准备；选择一个研究专题 | 发布有实际证据的版本报告，专题结论有基线和限制 |

训练、语音和动画后续按需要独立评估，不作为前几个月每天必须增加的功能。

## 每日提交完成条件

1. 写清当天要改变的具体行为。
2. 实现一项可观察的改进，完成相应验证。
3. 更新本表和相关文档的实际状态。
4. 提交并检查远端CI，最终报告提交链接和下一项任务。
