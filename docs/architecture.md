# 架构与一次请求

## 当前调用链

~~~text
网页或 HTTP 客户端
  → 创建会话：读取角色 → 保存角色快照和开场白
  → 提交文字与请求 ID
  → 会话服务：检查成功去重、取得会话锁、读取快照与成功历史
  → 上下文：system 角色规格、assistant 开场白、历史问答、user 当前输入
  → Provider：离线 mock 或兼容聊天消息接口的 HTTP 请求
  → 一个数据库事务：保存完整问答、成功响应和追踪
  → 返回回复，网页重新读取后端记录
~~~

调用模型期间不持有 SQLite 写事务。相同会话的发送和删除使用同一把进程内锁，不同会话互不阻塞生成。当前仅支持单进程。

## 职责与接口

| 部分 | 职责 |
|---|---|
| 角色规格 | 包内 JSON 校验；身份事实、价值观、表达方式、知识边界和对话示例；旧卡兼容 |
| 上下文构造 | 角色快照和有序消息；裁剪历史，报告裁剪信息 |
| Provider | `generate(GenerationRequest) → GenerationResult`；返回回复、模式、模型、用量和耗时 |
| SQLite 存储 | 会话、角色快照、成功完整轮次、可重放响应、失败及成功追踪 |
| 会话服务 | 输入校验、锁、幂等判断、调用与原子提交 |
| HTTP 和网页 | 新建、列表、恢复、删除、发送与追踪；使用 `textContent` 显示用户文字 |

`create_app(provider=None, settings=None)` 支持注入测试。旧 `POST /api/chat` 保持单轮语义，不保存会话，响应仍为三个字段。

## 角色与上下文

创建会话保存完整角色规格和配置开场白。已有会话按自己的快照运行，修改角色卡不会改变旧会话。角色信息供本机开发观察，没有隐藏设定保密机制。

默认最多纳入最近 10 个完整问答轮次，并受 16000 字符预算限制。角色规格、开场白与当前输入是必要内容；历史从最旧完整轮次排除，不能留下孤立消息。必要内容本身过长时明确失败，不丢弃设定或当前问题。数据库原文不会因裁剪删除。

追踪报告可用轮数、纳入轮数、是否裁剪和输入字符数。字符不是 token；没有摘要、检索或长期记忆提取。

## 提交、失败与追踪

成功后同 ID、同文字重试返回原结果，不再次调用适配器；同 ID、不同文字返回冲突。失败不存 user 半轮，保存错误类别与实际输入，可在之后重试。HTTP 适配器不自动重试。

成功的问答与结果原子保存。模型调用与 SQLite 无法形成分布式事务：上游成功而本地提交失败时，重试可能再次付费，不能声称端到端恰好调用一次。

追踪保存实际输入、模式、模型、耗时、用量和错误类别，不保存密钥或上游错误原文。删除会话级联删除消息、结果与追踪。工程追踪不证明回复符合角色。

网页刷新根据本地会话 ID 恢复后端历史；ID 已删除时回到可创建状态。发送失败保留输入，断线后同 ID、同文字重试可取回已提交结果。

## 运行与扩展边界

Python 包分发角色卡和 HTML/CSS/JS，无需前端构建或 CDN。数据库默认在当前工作目录的 `local_data`；本地原文和实验数据不能提交。

知识模块可提供带来源片段，记忆模块可提供可更正和删除的事实，游戏客户端可调用同一 HTTP 服务。当前版本尚未实现这些扩展；人设效果需要固定测试和真实对照实验。
